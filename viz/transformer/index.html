Transformers · The full architecture

The transformer, end to end

GPT, Claude, BERT, ViT — under the hood they are all the same machine. A transformer does one job: given some tokens, predict the next one. This page follows a sentence through the entire pipeline — tokenize, embed, attend, transform, predict — and then closes the loop to show how that single step, repeated, writes whole paragraphs. For the deep dive into the attention step itself, see the companion page Attention, explained slowly.

Before the architecture — the job

One task: predict the next token

Everything a language model does — answering questions, writing code, translating — emerges from one training objective: given a sequence of tokens, output a probability for every possible next token. The model that assigns high probability to the tokens that actually come next, across trillions of words of text, is forced to learn grammar, facts, and reasoning along the way.

“The cat sat on the ___” → mat 62% · floor 14% · couch 9% · …

Keep this in mind: the five stages below are just the plumbing between “a piece of text goes in” and “a probability for every next token comes out”.

Stage 1 · Text becomes pieces

Tokenization

Neural networks work on numbers, not letters. So the first step splits the text into tokens — words or sub-word chunks from a fixed vocabulary of ~50,000–100,000 entries — and replaces each with its ID.

Note that “The” and “the” map to the same ID — at this stage the model has no idea where in the sentence a token sits.

Why sub-words? A vocabulary can't hold every word ever written. Rare words get split into pieces — “tokenization” might become token + ization — so any text can be encoded, even words the model has never seen.

Stage 2 · Pieces become vectors

Embeddings + positions

Each token ID is looked up in a learned table and becomes a vector of hundreds of numbers (768 in BERT, 12,288 in GPT-3 — our toy uses 8). Words with similar meanings end up with similar vectors. But a lookup table is position-blind: both “the”s get the identical vector. So the model adds a positional encoding — a second vector that depends only on the slot the token occupies.

Each column is one token's embedding. The two “the” columns are identical — the model can't tell them apart yet.

Stage 3 · Words look at each other

Self-attention, in one picture

This is the transformer's signature move. Each token compares its query against every token's key and takes a weighted average of their values — so each word rebuilds its meaning from its context. Click a token in the top row to see where it sends its attention:

$$\text{Attention}(Q, K, V) = \text{softmax}\!\Big(\frac{QK^{\top}}{\sqrt{d_k}}\Big)\,V$$

Want the step-by-step version? The companion page Attention, explained slowly runs this computation by hand, number by number, with a draggable query vector. Here, the takeaway is just: after this stage, every token's vector contains information from the whole sentence. Real models run 12+ of these in parallel (multi-head attention), each head free to learn a different relationship.

Stage 4 · The repeating block

Attention + feed-forward, stacked ×N

Attention lets tokens exchange information; a small two-layer network (the feed-forward network) then processes each token on its own. Wrap both in residual connections (“add”) and normalization (“norm”) so gradients survive, and you have one transformer block. The whole model is just this block stacked — 12 times in BERT-Base, ~96 times at GPT-4 scale. Press play to trace the data flow:

Why alternate the two? Attention mixes across tokens but is mostly linear; the feed-forward network is nonlinear but sees each token alone. Alternating them, layer after layer, lets the model build increasingly abstract representations — early layers handle syntax, deeper layers handle meaning and facts.

Stage 5 · Closing the loop

Predict, append, repeat

The final layer outputs a probability for every token in the vocabulary. To generate text, the model samples one token, appends it to the input, and runs the whole pipeline again. That's the entire secret of text generation — one next-token prediction at a time. Press generate and watch it happen:

If you remember three things

The whole page in three sentences

One objective

A transformer maps a sequence of tokens to a probability distribution over the next token. Everything else is plumbing for that prediction.

Two alternating moves

Attention lets tokens exchange information; the feed-forward network processes each token alone. Stack the pair N times and representations grow abstract.

Generation is a loop

Predict the next token, append it, run again. Every paragraph a language model writes is this single step repeated.
